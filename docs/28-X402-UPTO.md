# x402 upto on Monad: signed a maximum, settled less

Scheme as described by Devansh Purohit (mentor thread `3e97258f`) and the EVM spec
(`x402-foundation/x402` `specs/schemes/upto/scheme_upto_evm.md`). Permit2 only. The buyer signs
`permit2Authorization.permitted.amount` as the maximum. `/verify` gets the maximum. `/settle` gets the
same signed payload with the actual charge. The facilitator moves only the actual charge.

## Run it

```bash
node --experimental-strip-types scripts/upto-testnet.mjs 100000 37000
```

Needs testnet USDC (`0x534b2f3A21130d7a60830c2Df862319e593943A3`) from the Circle faucet and a one-time
Permit2 approval, which the script sends if missing. `@x402/evm` is pinned at 2.27.0, which references
the upto proxy `0x4020A4f3b7b90ccA423B9fabCc0CE57C6C240002` deployed on Monad.

## The facilitator enforces it, not only us

Run with our own guard bypassed, on a fresh signature for a 50,000 maximum:

| attempt | result |
|---|---|
| settle 50,001 | 400 `invalid_payment_amount`, nothing moved |
| settle 12,000 | 200, `0x78d8bb6c3c7aaffc62cc9ff75178f589191f8f8df746cbad9ab19b957d207a79` |
| same signature again | 500 `unexpected_error`, nothing moved |

Buyer balance change across all three: -12,000. So the cap and single use hold at the facilitator
and the Permit2 nonce. The replay refusal arrives as a generic error rather than a named one, which is
worth knowing for anyone mapping errors to messages.

## What the signature does not cover

It caps the charge. It does not prove the usage behind it. `lib/upto.ts` keeps a `Meter` beside each
charge (unit, units used, price per unit) so a service can publish what it charged against and the
buyer can recompute the amount rather than only knowing it was bounded.

## Live on mainnet: Sentinel and Assay, 2026-09-29

`/api/service/{sentinel,assay}` now offer `upto` first and `exact` second. Ceiling 10,000 (0.01 USDC),
the old fixed price, so no buyer can pay more than before. Charge from `lib/metering.ts`:

    charge = min(ceiling, 2000 + 1000 per decided claim read)
    Sentinel refused on freshness: 0

Verify goes to the facilitator at the ceiling, the work runs, then settle goes at the charge. A zero
charge sends nothing on chain and the signature is marked spent so it cannot be replayed here.

Mainnet calls through the new route (self-payments: payer and payTo are both `0xDB6c…7777`):

buyer on mainnet is `0xa37c91711c2128d26a1c1964e247e81bb9466a9ee77a5c2bf0d9b0b697f9487d`.

Pay one yourself: `node scripts/pay-agent.mjs sentinel '{"agentId":10256,"maxAgeBlocks":64}' upto`.
